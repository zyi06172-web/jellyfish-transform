## 已知差距（哪块没做完 / 哪个模型没接 / 哪里将就了）

### 后端接口层面

- **`canvas-state` 接口是手写的，不是 codegen 生成的。** 我在后端源码里确认了 `GET/PATCH /api/v1/studio/projects/{project_id}/canvas-state` 真实存在（`backend/app/api/v1/routes/studio/projects.py:304-370`），但仓库里签入的 `front/openapi.json` 快照落后于后端源码、还没收录这两个接口，这个沙箱里也没法起后端重新生成。所以 `src/services/canvasState.ts` 是我按后端源码里的 Pydantic 字段手写的一个轻量 client，字段完全对齐。等你本机后端跑起来后执行一次 `pnpm run openapi:update`，理论上可以生成出等价的代码替换掉它——但我没法在这里验证生成结果是否分毫不差，请你替我跑一次确认。
- **没有独立的"画布"实体**，也没有 `/canvases` 接口——现状是"一个后端项目 = 一张画布"。计划书原文提到"一个项目下可有多个画布"，这个我做不到，因为后端没有对应的数据模型，这不是我能在前端假装出来的能力。
- **关键帧的"seed 固定"在后端没有真正落地。** 我查过 `ImageGenerationInput` 契约确实支持 `seed` 参数，但 `ShotFrameImageTaskRequest`、`StudioImageTaskRequest`、以及生成侧的 `build_frame_context` 全都没有把 `project.seed` 或任何 seed 值传给供应商。前端节点上显示的"seed"是我自己生成的一个展示用随机数，**不保证跨次重渲画面一致**。
- **累计花费是前端按单价表估算的，不是真实花费。** 后端目前完全没有持久化 DeepSeek/Seedream/Seedance 的 token 用量或费用（全仓库搜索 `token_usage`/`cost` 等字段是 0 命中），UI 上一律标"预估"，没有也不能伪装成真实数字。这是后端能力缺口，不是前端的锅，但也不是我这轮能补的（按你的要求，后端完全不能动）。
- **"镜头运动设计 6 项"**（跟随对象/运动路线/空间关系/主体关系变化/停顿点/结尾信息变化）后端没有对应字段，是前端从 `movement`/`screen_direction_guidance`/`composition_anchor`/`action_beats` 等已有字段做的启发式近似，节点里明确标了"近似推导，非后端结构化字段"，不是真的按公式 prompt 生成的结构化数据。

### 模型接入

- 女娲真实模型（DeepSeek / Seedream 5.0 Pro & Lite / Seedance 2.0 及其 fast/lite 变体）：下拉里正常可选。
- **GPT-image 2、Midjourney、Kling v3/v2.6、以及除 MiniMax 外的所有音频模型：下拉里能看到，标了"待接入"，选中后不会假装能出图/出声**，点生成会给出清楚的"未接入"提示，不会向后端发任何请求。
- MiniMax Speech 2.8 HD 虽是既定的短剧配音主模型，但后端目前没有任何音频供应商接入的痕迹，音频节点整体是"UI 完整、生成占位"的状态。

### 通用节点（文本/图片/视频/音频）的真实生成边界

计划书 §4/§11.3/§15 要求的通用四节点，UI（预设、模型、画质、比例、生成数量、放大编辑）全部按规格做了。但**这四个通用节点如果不连接短剧工作流的具体节点，点"生成"不会真的调后端**——因为后端根本没有一个"不挂靠任何实体的自由生图/生文"接口，所有生图能力都是挂在 character/scene/prop/shot 这些具体实体下面的。点生成时会弹出说明文字，而不是假装成功。短剧 workflow 里真正干活的是 10 个专用节点（script/character/location/prop/storyboard/shot_group/keyframe/shotlist_text/shotlist_render/video），这条链路是完整接通的。

### 电商画布

- **真实接通**：商品节点的"上传原图" "生成产品设定图（白底）" "生成多角度（左/右/背）"——复用了后端"道具（prop）"资产的图片槽位机制（`view_count=4` 时会自动预置 front/left/right/back 四个槽位），走的是和短剧道具完全一样的 `image-tasks/assets/prop/{id}/image-tasks` 接口，真实调用 Seedream。
- **占位**：场景合成、主图/详情页排版、营销海报——后端没有图像合成/排版能力，这几步做不出真东西，节点/预设里保留了入口，选中后是"待细化"提示，没有伪造结果。
- **agent 对话**：电商画布的右侧引导面板复用的是短剧 agent 后端（后端没有专门的电商对话流程），面板里加了醒目提示，引导用户直接用商品节点操作，而不是假装 agent 能懂电商流程。

### 素材库

- "素材库"（跨项目复用）和"回收站"两个 tab 只有空框架——计划书 §3.3 原文允许"本轮做出 tab 和空框架即可，卡片样式占位"，按这个来的，不是漏做。
